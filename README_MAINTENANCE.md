# Profile README — maintenance guide

## Repository layout

- `README.md` — GitHub profile content.
- `assets/profile-banner.svg` — lightweight profile banner.
- `assets/profile-hero.png` — retained source artwork from the previous version.
- `.github/workflows/` — automated contribution, metrics, 3D profile, and WakaTime jobs.
- `.github/scripts/update_waka.py` — updates the WakaTime section between its markers.
- `resume/` — resume documents retained from the supplied repository.

## Animation

The README uses a small animated typing image from `readme-typing-svg.demolab.com`.
It is intentionally limited to one line of rotating focus areas. If that third-party
service is unavailable, the rest of the README remains readable.

The contribution snake is generated by `.github/workflows/snake.yml` and published
to the `output` branch. The README references both dark and light variants.

## GitHub Actions secrets

Configure these under **Repository → Settings → Secrets and variables → Actions**:

- `WAKATIME_API_KEY` — required for live WakaTime statistics.
- `METRICS_TOKEN` — optional; the metrics workflow falls back to `GITHUB_TOKEN`.

Never put API keys or personal access tokens in README files, scripts, or workflow YAML.

## WakaTime setup

1. Install and authenticate the WakaTime extension in your editor.
2. Add `WAKATIME_API_KEY` as a repository Actions secret.
3. Run **WakaTime README** from the Actions tab using `workflow_dispatch`.
4. Confirm that the section between `<!--START_SECTION:waka-->` and
   `<!--END_SECTION:waka-->` is updated.

## Validate before pushing

Run:

```bash
python3 .github/scripts/validate_readme.py
```

The validator checks required sections, project links, local image references,
WakaTime markers, and the absence of student-year wording.
